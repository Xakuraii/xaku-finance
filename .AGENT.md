## 2. Product in one paragraph

XakuFinance is a private, single-user personal finance workspace. Users track accounts, income,
expenses, transfers, budgets, savings goals, and debts across USD and KHR. Every balance and report is
derived from an immutable double-entry ledger. Correctness, auditability, and data isolation outrank
visual polish and delivery speed. Golden (`#F0B90B`) is the brand accent; the product is dark-first
but fully usable in light mode.

## 3. Non-negotiable rules

Any change that violates one of these is rejected, regardless of tests passing.

1. **No floats for money.** Database: `BIGINT` minor units + `CHAR(3)` currency, or `NUMERIC`.
   Python: `Decimal`. TypeScript: `string`/integer, never `number` arithmetic on money.
2. **The ledger is the only source of balance truth.** No writable `balance` column. Aggregates read
   postings.
3. **Every journal entry balances to zero per currency.** Cross-currency entries route the residual
   through the FX clearing account.
4. **Posted history is immutable.** Corrections are reversing entries. Transaction edits append to
   `TransactionAudit` with `before`/`after`, revision, actor, and timestamp.
5. **Status semantics:** `pending` and `cancelled` never affect balances; only `completed` posts.
6. **Transfers, opening balances, savings earmarks, and debt principal are not income or expense.**
   Interest and fees are expenses.
7. **Splits sum exactly to the parent amount** in the same currency. Validate on write and re-validate
   on edit.
8. **All financial writes are atomic.** Wrap services in `transaction.atomic()`, lock affected ledger
   accounts with `select_for_update()`, and never leave partial state.
9. **Every query is workspace-scoped.** Authorization is enforced server-side from
   `request.user.workspace`; a client-supplied workspace id is never trusted.
10. **No secrets in source.** `.env` only, `.env.example` documents keys with fake values.
11. **AI never computes money.** Insights receive server-computed summaries; the model explains them.
12. **Never destroy financial history.** Archive, reverse, or soft-delete; hard deletion only through
    the privacy deletion workflow with its documented backup-retention caveat.

## 6. Workflow for every task

1. Read the requirement ID in `docs/SRS.md` and the relevant ADRs.
2. Write or update the failing test first (`docs/TESTING.md` names the required cases).
3. Implement the smallest change that passes, inside a service function — not in a view or serializer.
4. Run the targeted test, then the domain suite, then the integrity suite.
5. Update docs that the change invalidates (API spec, accounting rules, glossary, changelog).
6. Report: what changed, files, decisions, DB changes, tests run, actual results, limitations, next step.

Detailed workflow: `.agent/workflows/feature-delivery.md`.
Financial change gate: `.agent/workflows/financial-change.md`.

## 7. Definition of done

- Requirement ID implemented and traceable to tests.
- Migration committed; forward and reverse both run cleanly.
- Atomicity and idempotency proven by a test.
- Workspace isolation proven by a cross-tenant test.
- `ruff`, `mypy`, `pytest` green; frontend `typecheck`, `lint`, `test`, `build` green.
- OpenAPI regenerated and validated.
- No float money anywhere in the diff.
- Docs updated; limitations listed honestly.

## 8. Things agents must not do

- Do not scaffold "all features" in one pass or generate placeholder implementations.
- Do not add a dependency without recording why in `docs/adr/` or the PR notes.
- Do not create fake seed data in production migrations. Demo data lives in a dev-only command.
- Do not weaken `ATOMIC_REQUESTS`, auth checks, throttles, or CORS to make a test pass.
- Do not rewrite or squash existing migrations after they have been applied anywhere shared.
- Do not reintroduce receipt upload/OCR, multi-workspace collaboration, or bank syncing; they are
  explicitly out of V1 scope.
